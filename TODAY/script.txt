# IMPORTANT: Cisco SNMP configuration

For your Cisco IOL devices, we should use **SNMPv3**, not SNMPv2c, eventually.

For initial lab testing, SNMPv2c is easier.

Example:

```cisco
conf t

snmp-server community Monitoring123 RO

end

write memory
```

Then the SNMP Exporter configuration must know the community string.

⚠️ **This is the one part I do not want you to blindly configure yet.**

The default SNMP Exporter configuration may use a different SNMP authentication profile than your devices. Before we configure all of your Cisco devices, we should verify the SNMP Exporter's current `snmp.yml` and configure the authentication correctly.

# Cisco IP SLA — Important distinction

There are **two types of monitoring** you will have.

## Method 1: Blackbox ICMP

Prometheus sends:

```text
Prometheus

     ↓

Blackbox Exporter

     ↓

PING

     ↓

Cisco Router
```

This tells you:

```text
Is the device reachable?

What is the latency?

Did packets fail?

What is packet loss?
```

---

## Method 2: Cisco IP SLA

Cisco itself generates the probe:

```text
Cisco Router A

     ↓

IP SLA Probe

     ↓

Destination

     ↓

Cisco Router A
```

For example:

```cisco
ip sla 1

 icmp-echo 10.10.10.2

 frequency 10

ip sla schedule 1 life forever start-time now
```

Then Cisco stores statistics such as:

```text
Round-trip time

Packet loss

Success/failure

Jitter
```

The monitoring server retrieves those results using SNMP:

```text
Cisco IP SLA

      ↓

SNMP

      ↓

SNMP Exporter

      ↓

Prometheus

      ↓

Grafana
```

## My recommendation for IP SLA

**Do not add a random IP SLA SNMP module yet.**

IP SLA monitoring requires adding the Cisco RTTMON MIB/OIDs correctly to the SNMP Exporter configuration. I would build that as the **next step**, after we verify:

1. Your Cisco IOL L3 image supports IP SLA correctly.
2. Your IOL image supports the required SNMP MIB.
3. We confirm SNMPv2c or SNMPv3.
4. We test one IP SLA operation.
5. Then we add the correct IP SLA metrics to Prometheus.

That prevents us from building a huge configuration that fails because the particular IOL version doesn't expose the expected OIDs.
